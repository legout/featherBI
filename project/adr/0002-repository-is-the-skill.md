# ADR 0002: The repository is the skill

Status: accepted (owner, 2026-11-24).

## Context

The previous featherBI shipped as an npm CLI (`featherbi@0.3.0`) plus a skill copied out of it. Two products, two release paths and a `setup` command were part of the complexity that made it unusable. Spec 0001 makes the skill, with its scripts and templates, the product.

## Decision

- This repository contains exactly one installable skill at `skill/featherbi/` (`SKILL.md`, `scripts/`, `templates/`, `references/`, prebuilt `assets/`).
- Users install it with `npx skills add legout/featherbi` (global or project). There is no npm package and no `setup` command.
- Build-time requirements are the DuckDB CLI ≥ 2.0 and Node ≥ 22 already on the machine; the skill's scripts use no npm dependencies at dashboard-build time.
- Release-time tooling (Tailwind/DaisyUI CSS build, library pin updates, tests) lives outside `skill/` and is never needed by users.
- The npm package `featherbi` is deprecated with a message pointing to the repository, or unpublished where the npm registry allows it.

## Consequences

- Updates arrive through `npx skills update`; versions are Git tags.
- Users who installed `featherbi` from npm see the deprecation notice; old versions stay available unless the registry permits removal.
- Generated CSS and pinned library versions are committed artifacts, regenerated by the release tooling.
