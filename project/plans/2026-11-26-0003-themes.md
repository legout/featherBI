## Goal

`theme:` in `dashboard.yaml` selects a built-in theme or an author's theme file; colours, palette, radius, font and logo are embedded in every output mode. Spec 0003 acceptance 1–6 must hold.

## Constraints for sequencing

- **Mechanism:** the prebuilt `assets/app.css` keeps DaisyUI's `winter`/`night`. A theme adds one `<style>` block after it that sets the DaisyUI colour variables (`--color-*`, `--radius-*`) for `[data-theme=…]` light and dark, plus `@font-face` when a font file is given. No Tailwind at build time (ADR 0002). The existing template and renderer read colours from these variables already (`chartTheme()` in `assets/renderer.js`), so charts follow.
- **Default byte-identical:** without `theme` the render output must not change at all (spec acceptance 1). The theme block is emitted only when `theme` is set.
- **Reuse:** YAML via the vendored parser already used by `scripts/lib/config.mjs`; files inlined as data URLs like `scripts/lib/assets.mjs` does.
- **Non-goals** (spec): brand themes in the repo, layout changes, custom CSS, a theme picker.

- **Files:** `skill/featherbi/scripts/lib/theme.mjs` (new: `loadTheme(value, configDir) -> { css, logo, schemes } | null`, validation, contrast check), `skill/featherbi/scripts/lib/config.mjs` and `skill/featherbi/schema/dashboard.schema.json` (`theme` key), `skill/featherbi/scripts/lib/render.mjs` (insert the theme `<style>` after the app CSS, the logo before the title, `data-theme` names), `skill/featherbi/templates/dashboard.html` (logo slot; hide the toggle when one scheme), `skill/featherbi/assets/renderer.js` (palette override in `chartTheme()`; toggle switches between the theme's light/dark names), `skill/featherbi/themes/default.yaml` (the format's first instance: today's look), `tests/theme.test.mjs` (new), `tests/theme.spec.mjs` (new), `CONTEXT.md` (two terms).
- **Interface produced:** theme file format exactly as spec 0003 §Theme file; built-in lookup `skill/featherbi/themes/<name>.yaml`.
- **Behavior:** as spec 0003 §Behaviour. Validation runs before any source is read; error text `theme <file>: <key>: <problem>`. Contrast ratio per WCAG 2.x relative luminance, warning text names the pair, scheme and ratio with two decimals.
- **Validation (normal risk):** `new-test`.
  - node:test (`tests/theme.test.mjs`): each spec validation case → build fails, no HTML (spec acceptance 5); contrast warning for `#999999` on `#ffffff` reports `2.85:1` (spec acceptance 6; oracle: WCAG formula by hand, L(#999)=0.3185 → (1.05)/(0.3685)=2.85); hand fixture without `theme` gives the same SHA-256 as `main` before this task (acceptance 1; record the pre-change hash in the test from a build of `main`, not from the new code).
  - Playwright (`tests/theme.spec.mjs`, Chrome + Firefox): a test theme file with both schemes, palette, font and logo, built `--offline`, every non-`file:` request blocked: `--color-primary` computed value matches the file in light and after the toggle in dark, first chart series colour = `palette[0]`, logo visible, body font family applied (acceptance 3); a light-only file hides the toggle under `prefers-color-scheme: dark` emulation (acceptance 4).
  - Focused cmd: `node --test tests/theme.test.mjs && npx playwright test tests/theme.spec.mjs --workers=1`.
- **Done:** the tests above are green and CI is green.
