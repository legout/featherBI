## 1. Scope

featherBI gains a theme-token system: a fixed, validated set of design tokens that the compiler bakes into the typed viewer as CSS variables, a registered ECharts theme, and AG Grid variable overrides. Built-in Siemens Industrial Experience themes (dark and light) ship as preset token sets baked through the same code path as custom token sets. The authoring skill turns a natural-language style request into a token file.

Non-goals: KPI delta indicators (require a previous-period query; separate work); porting `neutral` or `daisyui` onto the token system; automatic or recipient-side theme switching; Perspective internals beyond supported variables and parts; accessibility certification (contrast checking is advisory, see §5).

## 2. Theme selection

- `theme:` enum gains `siemens-ix-light`. `siemens-ix` is now the **dark** Siemens Industrial Experience theme; previously it was a shell-class adapter. This is a documented behavior change for the (explicit-only) `siemens-ix` selection.
- The explicit-selection rule is preserved: `siemens-ix` and `siemens-ix-light` are selected only when the user explicitly asks, never inferred from organization or data names. `neutral` remains the default.
- Optional `themeTokens: <path>` names a YAML token file relative to the project, producing a **custom theme**. `themeTokens` is valid only with the default `neutral` shell; combining it with `theme: daisyui|siemens-ix|siemens-ix-light` is a compile error naming both fields (TT-04).
- `theme.css` remains allowed alongside `themeTokens`. The baked theme is injected first; scoped author `theme.css` applies after it and wins on conflict (documented escape hatch, TT-08). The existing scope transform (no `@import`, no remote URLs, no hiding of status/error/progress affordances) is unchanged.

## 3. Token file contract

`theme.tokens.yaml`, schema version 1:

```yaml
version: 1                       # optional, default 1
font: Inter, ui-sans-serif, system-ui, sans-serif   # optional, this default
fontMono: "JetBrains Mono", ui-monospace, monospace # optional
radius: 8                        # optional px integer 0–24, default 8
surface: "#000028"               # required — page background
surface2: "#0d0d40"              # required — raised/input surface
text: "#e6e9f8"                  # required
textDim: "#8f96c4"               # required — labels, hints, axis text
border: "#262660"                # required
accent: "#00e6dc"                # required — primary action, selected marks, heat max
accentContrast: "#000028"        # required — text on accent
success: "#00ffb9"               # required
warning: "#ffb35c"               # required
danger: "#ff6b8a"                # required
chart:
  palette: ["#00e6dc", "#00ffb9", "#009999", "#8f8ff0", "#66d9ff"]  # required, 3–8 colors
  heatMin: "#161650"             # optional; defaults to surface2
```

Colors are `#rgb`, `#rrggbb`, or `rgba(...)`; anything else is a compile error. Font stacks must not contain `@import`, `url(`, or scheme text (CSP); violations are compile errors. Unknown keys are compile errors naming file and key. Missing required keys are compile errors naming the key. Errors carry filename/line/column in the established compiler style.

## 4. Baked theme (compiled config and runtime)

- The compiler validates the token file and bakes into the compiled config: `theme: { name, css, echarts }` where `css` is a scoped variable block (including AG Grid `--ag-*` overrides mapped from the same tokens) and `echarts` is a complete ECharts theme object.
- Built-in presets (`siemens-ix`, `siemens-ix-light`) are shipped token sets baked by the identical path; there is no separate preset-only theming code.
- At boot the runtime injects `css` once, registers `echarts` once under a fixed name, and initializes every chart with it. The ECharts theme maps tokens as: series palette ← `chart.palette`; text/legend/axis labels ← `textDim` in `font`; axis lines ← `border`; split lines ← `border` at reduced alpha (baked; if `border` is `rgba()` it is used as-is); heatmap `visualMap.inRange` ← `[heatMin, chart.palette[0]]`; number/mono contexts (numeric table columns, status text) ← `fontMono` when present.
- Only the selected theme ships in the artifact (unchanged rule).

## 5. Validation and accessibility floor

- Contrast is checked at compile time for the pairs `text`/`surface`, `textDim`/`surface`, `accentContrast`/`accent` (4.5:1 targets), `accent`/`surface` and each `chart.palette` entry against `surface` (3:1). Below the target the compiler prints one warning per pair with the measured ratio; **the build succeeds** (TT-03). Warnings are never silent.
- Baked themes must keep required status, error, progress, focus, and label affordances visible; this restates the existing V2-05 rule and applies to presets and custom themes alike (TT-09).

## 6. Component markup upgrades

These apply to all themes, including `neutral` and `daisyui`:

- **KPI / metric-group:** each metric renders as label above value, one metric per visual row; values are never concatenated inline. This fixes the current inline-gluing defect (values rendering as e.g. `342,4683.94705985.204`). A unit may render at reduced size beside the value. Delta indicators are out of scope (see §1).
- **Filter bar:** filters render in one contained bar region with a small caption label above each control, replacing bare `fieldset`/`legend` chrome.
- **Boolean filter:** renders as an All / Yes / No segmented control standing for `null` / `true` / `false`, keyboard-operable in that cycle and back to All (existing interaction contract preserved, TT-07).
- **Table:** AG Grid remains themed through supported `--ag-*` variables only, now mapped from tokens by the baked CSS.

Markup hooks (classes/data attributes) change with this work; the CHANGELOG documents the change and the in-repo examples' `theme.css` is updated (accepted breakage, owner decision 2026-09-28).

## 7. Authoring flow (skill)

During the appearance step of the interview, the author may describe a style in natural language (e.g. "minimal like Vercel", "premium dark"). The agent then authors `theme.tokens.yaml` directly — never free-form chart CSS — compiles, fixes every error, presents the preview, and iterates on the token file alone. The skill documents the token contract, the warning semantics, and the rule that `siemens-ix*` remains explicit-only. Skill references `components.md`, `themes-and-css.md`, and `interview.md` are updated in the same work.

## 8. Acceptance examples

- **TT-01** — A project with a valid `theme.tokens.yaml` compiles; the artifact renders with baked variables, charts use the palette and token axis styling, and the AG Grid table matches the theme.
- **TT-02** — A token file with an unknown key fails compilation with an error naming the file and key; an invalid color or a font stack containing `url(` fails the same way.
- **TT-03** — A token file whose `text`/`surface` pair is below 4.5:1 compiles successfully and prints a warning naming the pair and the measured ratio.
- **TT-04** — `themeTokens` combined with `theme: daisyui` fails compilation naming both fields.
- **TT-05** — `theme: siemens-ix` renders the dark Siemens preset and `theme: siemens-ix-light` renders the light preset; neither is ever selected implicitly.
- **TT-06** — A metric-group with three fields renders three label-over-value rows; no values are glued together.
- **TT-07** — The boolean filter shows All / Yes / No segments; keyboard operation cycles All → Yes → No → All and produces the `null` / `true` / `false` filter values.
- **TT-08** — With both `themeTokens` and `theme.css` present, the author CSS applies after the baked theme and wins conflicts; the scope transform still rejects imports and remote URLs.
- **TT-09** — Dashboard ready/status, error, and progress affordances remain visible under `siemens-ix`, `siemens-ix-light`, and a custom token theme.

## 9. Testing obligations

- Compiler token validation: unit tests (`new-test`) covering TT-02, TT-03, TT-04 and the baked-output shape of TT-01.
- Browser gate (`npm run test:browser`): `siemens-ix`, `siemens-ix-light`, and one custom-token project covering TT-05–TT-09; `npm run check` for every code change.
- Visual baseline: the mockups in `~/coding/libs/featherbi-mockups/shots/` are the reference for the two presets; exact pixel equality is not required, gross divergence is a review finding.
- No exhaustive theme × component × filter matrices; named failure modes only.
