# Spec 0003: themes and theme files

Status: **approved**, revision 1 (owner, 2026-11-26, "genehmigt"). Owner choices so far (2026-11-26): a theme file the author supplies, plus three neutral built-in themes; brand-like themes (Siemens, Audi, Vercel, Tesla, …) are **not** shipped in this repository, each author builds their own from the template.
Builds on: [spec 0001](2026-11-24-0001-featherbi-v1.md) r4 (layout, light/dark toggle, chart colours from the theme) and [ADR 0001](../adr/0001-dashboard-stack.md) (DaisyUI 5 + Tailwind 4, CSS prebuilt and inlined).

## Goal

An author picks how a dashboard looks with one config key: a built-in theme by name, or a theme file with their own colours, chart palette, font and logo. The result is still one self-contained HTML file; `--offline` keeps working.

## Interface

`dashboard.yaml` gains one optional key:

```yaml
theme: corporate            # a built-in theme
theme: ./brand/theme.yaml   # or a theme file, relative to the config file
```

Without `theme` the page looks exactly as today (built-in `default`: DaisyUI winter / night).

### Theme file

```yaml
name: Acme                      # shown nowhere; used in error messages
light:                          # at least one of light / dark
  primary: "#0b5fff"            # any of the DaisyUI colour tokens, hex or oklch()
  primary-content: "#ffffff"
  base-100: "#ffffff"
  base-content: "#1a1a1a"
  # optional: secondary, accent, neutral, base-200, base-300, info, success, warning, error and their -content
dark:
  primary: "#6ea0ff"
  base-100: "#111418"
  base-content: "#e8eaed"
palette: ["#0b5fff", "#ff7a00", "#00a37a"]   # optional chart series colours; default: derived from the theme as today
radius: 0.5rem                  # optional: corner radius of tiles and controls
font:                           # optional
  family: "Acme Sans, system-ui, sans-serif"
  file: ./AcmeSans.woff2        # optional; embedded; the author is responsible for its licence
logo: ./logo.svg                # optional; SVG or PNG, embedded, shown left of the title
```

- Tokens that are left out fall back to the `default` theme for that scheme.
- With both `light` and `dark` the toggle stays and the first view follows the viewer's system setting (as today). With only one, the toggle is hidden.
- Built-in themes are theme files in the skill (`skill/featherbi/themes/<name>.yaml`) in exactly this format: `default`, `corporate` (sober blue/grey, square corners), `minimal` (black/white, one accent), `high-contrast` (WCAG AAA text contrast, light and dark).
- `references/themes.md` documents the format, the four built-ins, a template file and a worked example for a fictitious brand ("Acme"), including how to take colours from a brand guide.

## Behaviour

- **Build:** the theme is read and validated before any source is read. Its colours become CSS custom properties inlined into the page; the font file and logo are inlined as data URLs. Default, `--offline`, `--split` and `--remote` all embed the theme the same way.
- **Charts, grid, pivot, Explore** take their colours from the active theme as today; `palette`, when given, replaces the derived series colours in both schemes.
- **Validation** (each stops the build with an error naming the theme file and the key; no HTML is written): unknown built-in name; file not found; unknown key; a colour that is not hex or `oklch()`; a font or logo file that is missing, of the wrong type, or larger than 500 KB (font) / 200 KB (logo).
- **Contrast warning:** when `base-content` on `base-100`, or `primary-content` on `primary`, is below 4.5:1 in a scheme, the build warns (it does not fail) and names the pair and the ratio.
- **Determinism:** the same config, theme file and assets give byte-identical HTML.

## Non-goals

- Themes that copy third-party brands, their logos or licensed fonts, inside this repository.
- Layout changes per theme (grid, tile order, spacing beyond `radius`), custom CSS, per-tile colours beyond the existing ECharts `option`.
- A theme gallery or picker in the page.

## Acceptance examples

1. **Default unchanged.** A config without `theme` builds byte-identical HTML to the build before this change, for the hand fixture.
2. **Built-in theme.** `theme: corporate` on the hand fixture: the page's `--color-primary` matches the theme file in light and dark, chart series colours change with the toggle, 0 console errors in Chrome and Firefox.
3. **Theme file.** The Acme example (both schemes, palette, font file, logo): logo visible left of the title, the font applied to body text, the first chart series in `palette[0]`, all of it with every non-`file:` request blocked in an `--offline` build.
4. **Single scheme.** A theme file with only `light`: no toggle, light colours even when the viewer prefers dark.
5. **Errors.** Each validation case above stops the build with an error naming the file and key, and no HTML is written.
6. **Contrast warning.** A theme with `base-content` `#999999` on `base-100` `#ffffff` builds and warns with the ratio (2.85:1).
